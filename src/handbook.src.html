B1What is Claude

Claude is an AI assistant made by Anthropic. You type or speak a request in plain English. Claude writes, explains, plans, summarises, reads your files, and writes code.

The Claude models

A model is the brain that writes the answer. Bigger models think harder. Smaller models answer faster.

You pick the model from a menu near the message box. If you're not sure, keep the default.

B2Install the desktop app

Check your computer first: macOS 13 or newer, or Windows 10 (version 1809) or newer. A Linux version is in beta.

  1. Download the installer: Claude for Mac. One file works on Intel and Apple-chip Macs.
  2. Open the downloaded .dmg file and drag Claude into Applications.
  3. Open Claude from Applications.
  4. Sign in with your Claude account, or create one.
  5. Type your first message.
  1. Download the installer: Claude for Windows. An ARM64 build also exists.
  2. Run the downloaded .exe file and follow the prompts.
  3. Open Claude from the Start menu.
  4. Sign in with your Claude account, or create one.
  5. Type your first message.
The Code tab. The desktop app has a Code tab that runs Claude Code without a terminal. You choose a folder, pick a model, and describe the task. The Code tab needs a Pro plan or higher.

B3Your first chats

A good prompt has three parts. Say what you need, give the background, and say what the answer should look like. The weak prompt below has only the first part. The better prompt has all three.

PartWeak promptBetter prompt
The task"Write an email.""Write an email asking my manager for Friday off."
The backgroundMissing, so Claude has to guess"I finished the report early. Keep it polite and short."
The shapeMissing, so Claude picks any length"Under 80 words, with a subject line."

Prompts to try today

  • "Summarise this PDF in 5 bullets." (attach the file)
  • "Make a weekly meal plan for two, as a table."
  • "Explain this error message in simple words."
  • "Ask me 5 questions, then write my cover letter."
Check the important facts. Claude can be wrong. For money, health or legal questions, check the answer with a trusted source.

I1Claude Code in the terminal

Claude Code is Claude for building software. Claude Code reads the files in a folder, edits them, and runs commands. Before risky steps, Claude Code asks you first.

You need: a Pro, Max, Team or Enterprise plan, 4 GB of memory or more, and an internet connection. The Free plan does not include Claude Code.

Open a terminal

ComputerHow
MacPress Cmd + Space, type Terminal, press Enter.
WindowsClick Start, type PowerShell, press Enter.

Install

curl -fsSL https://claude.ai/install.sh | bash
irm https://claude.ai/install.ps1 | iex

Also install Git for Windows. Claude Code works best with it.

curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

Homebrew and WinGet work too: brew install --cask claude-code or winget install Anthropic.ClaudeCode.

Start and sign in

  1. Go to a project folder: cd Documents/my-project
  2. Type claude and press Enter.
  3. A browser window opens. Sign in with your Claude account.
  4. Back in the terminal, ask: "What does this project do?"

Commands worth knowing

Update and uninstall

The standard install updates itself. For Homebrew or WinGet, run brew upgrade claude-code or winget upgrade Anthropic.ClaudeCode. To uninstall on Mac or Linux:

rm -f ~/.local/bin/claude
rm -rf ~/.local/share/claude
No terminal? Claude Code also runs in the desktop app's Code tab, in VS Code and JetBrains editors, and on the web at claude.ai/code.

I2How Claude Code works

Claude Code works in a loop. Claude Code reads, plans, acts, and checks, and repeats until the task is done. You stay in charge of every risky step.

Skills, explained

Think of a skill as a recipe card. Without one, you explain the same job to Claude every time: which file to read, what headings to use, how long to make it. With a skill, you write those steps once, and Claude follows them whenever that job comes up.

A skill is a folder with one file in it, SKILL.md. The top of the file holds a name and a one-line description. The rest holds the steps.

# .claude/skills/weekly-report/SKILL.md
---
name: weekly-report
description: Write my weekly status report. Use when I ask for a weekly update.
---
1. Read the notes in reports/notes.md.
2. Group the items under Done, In progress and Blocked.
3. Keep it under 200 words, in plain English.
StepWhat happens
1. You save the skillClaude Code sees the skill's name and one-line description. The full steps stay unread for now.
2. You ask for the jobYou type "write my weekly update". The request matches the description, so Claude opens the skill and reads the steps.
3. Claude follows the stepsSame headings, same length, every week.
Or: you call it by nameType /weekly-report to run the skill directly.

A skill can also carry helper files, such as a script or a template, in the same folder. Skills saved in ~/.claude/skills/ work in every project. Skills in a project's .claude/skills/ folder work in that project, for everyone who opens it.

I4Connect tools

Out of the box, Claude only sees what you type or attach. A connector (in the apps) or an MCP server (in Claude Code) lets Claude read and act on a real tool, such as your Drive, GitHub or a database. Both use the same standard, called MCP. The Advanced section explains how MCP works inside.

In the Claude app

  1. Open Settings → Connectors. Newer versions may label the menu Customize → Connectors.
  2. Click Discover and pick a tool, such as Google Drive.
  3. Click Connect and sign in to that tool in the browser window.
  4. Ask: "Find last week's meeting notes in my Drive."

Tools not in the list can be added as a custom connector by pasting the MCP server's URL. Every paid plan can add custom connectors. On Team and Enterprise, the owners add connectors for the whole organisation.

In Claude Code

# a remote server, reached over the internet
claude mcp add --transport http notion https://mcp.notion.com/mcp
# a local server, started on your computer
claude mcp add db -- npx -y @bytebase/dbhub --dsn "postgresql://..."

Then type /mcp inside Claude Code to check the connection and sign in. claude mcp list shows every server you added.

Scope flagWho gets the serverSaved in
--scope localThe default. Only you, only this project.~/.claude.json
--scope projectEveryone who opens this project..mcp.json in the project
--scope userOnly you, in every project.~/.claude.json
# .mcp.json, shared with your team through git
{
  "mcpServers": {
    "notion": { "type": "http", "url": "https://mcp.notion.com/mcp" }
  }
}
Safety. A connector can see whatever its account can see. Add only tools you trust, and give them only the access they need.

Level 3 of 3AdvancedHow MCP works inside, where each part runs, and how to build your own.

A1MCP: the parts

MCP (Model Context Protocol) is an open standard for connecting AI apps to tools and data. MCP has three roles.

RoleWhat it doesExample
HostThe AI app you use. The host holds the chat, talks to the model, and asks your permission.Claude Code, Claude Desktop, claude.ai, your own app
ClientA connector inside the host. The host runs one client per server.Built into the host
ServerA small program that offers tools and data to any MCP host.A GitHub server, a files server, your own server

What a server can offer

PrimitiveMeaningExample
ToolsActions Claude can ask to runcreate_issue, weather_current
ResourcesData Claude can readA file, a database row
PromptsReady-made prompt templates"Review this pull request"

How the messages travel

Every message is JSON-RPC 2.0, a simple JSON format for requests and replies. Two transports carry the messages:

TransportWhen
stdioThe server runs on the same computer as the host. The host starts the server as a child program and they talk through standard input and output.
Streamable HTTPThe server runs somewhere else and is reached over the internet. The older HTTP + SSE transport is deprecated.

The current spec is dated 2026-07-28: modelcontextprotocol.io/specification.

A2How a tool is defined

A tool is a small JSON description. The server writes the description, and the model reads it to decide when and how to use the tool. A clear description matters as much as the code behind it.

# a tool definition, as the server sends it in tools/list
{
  "name": "weather_current",
  "title": "Weather Information",
  "description": "Get current weather for any location worldwide",
  "inputSchema": {
    "type": "object",
    "properties": {
      "location": { "type": "string", "description": "City name or coordinates" },
      "units": { "type": "string", "enum": ["metric", "imperial"], "default": "metric" }
    },
    "required": ["location"]
  }
}
FieldRequiredWhat it is for
nameYesThe ID the model uses to call the tool. Letters, numbers, _ and -, up to 128 characters.
descriptionYesPlain words telling the model what the tool does and when to use it.
inputSchemaYesA JSON Schema for the inputs: names, types, which are required.
titleNoA friendly name to show people.
outputSchemaNoThe shape of the result, if the tool returns structured data.
annotationsNoHints about behaviour, such as whether the tool only reads.

The two calls

# host → server: run the tool
{ "jsonrpc": "2.0", "id": 7, "method": "tools/call",
  "params": { "name": "weather_current", "arguments": { "location": "Pune" } } }
# server → host: the result
{ "jsonrpc": "2.0", "id": 7,
  "result": { "content": [ { "type": "text", "text": "24°C, cloudy" } ], "isError": false } }

tools/list asks a server for all its tool definitions. tools/call runs one tool. If the tool fails, the result carries "isError": true and a message the model can read.

A3How Claude uses a tool, step by step

Follow the numbers down the left. Solid arrows are requests. Dashed arrows are replies.

The key pointThe model never runs anything. The model only writes a request: "please call weather_current with Pune". The host decides whether to allow the call, and the MCP server runs the code.

A4Claude side or server side?

Both, for different jobsChoosing a tool happens on Claude's side, in the model. Running the tool happens on the server side, in the MCP server. The host app sits between them and carries the messages.

Where the server itself runs depends on how you connect. The three common setups:

SetupWho calls the serverWhere the tool runsNeeds to be public?
A. Claude Code + local serverClaude Code on your computerYour computerNo
B. Claude Code + remote serverClaude Code on your computerThe server's hostReachable from your computer
C. claude.ai / desktop custom connectorAnthropic's cloudYour serverYes, reachable from the internet

Custom connectors sign in with OAuth. Claude supports dynamic client registration and token refresh, and redirects to https://claude.ai/api/mcp/auth_callback after sign-in.

A5MCP vs API

An API is one service's own set of URLs and rules. MCP is one shared plug shape that any AI app can use for any tool. An MCP server usually calls a service's API underneath. So MCP does not replace APIs. MCP wraps APIs in a form AI apps can discover and use.

APIMCP
What it isOne service's interfaceOne standard for AI apps to find and use tools
Built forAny programAI apps and models
How tools are foundA developer reads the docs and writes codeThe host asks tools/list while running, and the model reads the descriptions
Work per new appNew code for every serviceNone, if the app speaks MCP
Who decides what to callThe developer's codeThe model, with the host's permission

Tools in the Claude API, without MCP

The Claude API has its own tools parameter. The flow is the same as MCP: Claude replies with a tool_use block, your code runs the tool, and you send back a tool_result block. The only difference is that your code holds the tools, with no MCP server involved. The schema field is spelled input_schema in the API and inputSchema in MCP.

A6Connect your own app

"Connecting your app to MCP" means one of two things. Pick the path that matches your goal.

Path 1. Let Claude use your app: build an MCP server

  1. Write a server that wraps your app's actions as tools. The Python SDK keeps a small server very short:
# server.py, using the official Python SDK (pip install mcp)
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("weather")

@mcp.tool()
def weather_current(location: str) -> str:
    """Get current weather for a city."""
    # call your real API or database here
    return f"24°C, cloudy in {location}"

if __name__ == "__main__":
    mcp.run()  # stdio

The SDK turns the function name, the docstring and the type hints into the tool's name, description and inputSchema. A TypeScript SDK also exists: @modelcontextprotocol/sdk.

  1. Test the server with the MCP Inspector, which lists your tools and lets you call them by hand.
  2. Add the server to Claude Code: claude mcp add weather -- uv run server.py
  3. To use the server in claude.ai, run it over Streamable HTTP on a public URL, add OAuth, and add the URL as a custom connector.
stdio servers must not print. On stdio, standard output carries the JSON-RPC messages. A stray print() breaks them. Log to standard error instead.

Path 2. Use Claude inside your app: call the API with tools

# your app, using the Anthropic Python SDK
import anthropic
client = anthropic.Anthropic()

tools = [{
    "name": "weather_current",
    "description": "Get current weather for a city",
    "input_schema": {"type": "object",
                     "properties": {"location": {"type": "string"}},
                     "required": ["location"]}
}]

msg = client.messages.create(
    model="claude-sonnet-5-5", max_tokens=1024, tools=tools,
    messages=[{"role": "user", "content": "Weather in Pune?"}])

# msg.content holds a tool_use block. Run the tool yourself,
# or forward it to an MCP server with tools/call, then send
# the output back as a tool_result block in the next request.

To use existing MCP servers here, make your app an MCP client with the MCP SDK. Call tools/list, pass those tools to Claude, and turn each tool_use into a tools/call.

Security checklist for tools

  • Give each server the smallest access that works, such as read-only tokens.
  • Treat tool results as untrusted text. A web page or file can contain instructions aimed at the model.
  • Keep approval on for tools that write, delete, send or pay.
  • Install servers and plugins only from sources you trust.
